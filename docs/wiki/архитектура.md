# Архитектура

## Кратко

3D-футбольная игра на C++17/CMake 3.16+: форк заброшенного GameplayFootball, обновлённый под
SDL3 (SDL3_image/SDL3_ttf)/OpenGL/OpenAL/Boost/SQLite3 и собранный по изменениям Google Brain.
Работает offline, локально: один процесс `gameplayfootball`, окно + ввод с клавиатуры/геймпада.
Движок «Blunted2» живёт в `src/` рядом с игрой (не отдельная библиотека).

## Сквозной путь

```
main() → Properties(football.config)
  → Database.Load("databases/default/database.sqlite")
  → SystemManager: RegisterSystem(GraphicsSystem, AudioSystem)
  → Scene2D + Scene3D → ObjectFactory
  → Scheduler: TaskSequence "game" (10 мс) + TaskSequence "graphics" (непрерывно)
  → Run()
```

Поток данных за тик:

1. **game** (тик `physics_frametime_ms` = 10 мс): `MenuTask::Get` → `GameTask::Get`
   (обрабатывает messageQueue, `match->Get()` читает ввод) → `GameTask::Process`
   (`match->Process()` считает симуляцию, потом `PreparePutBuffers`).
2. **graphics** (непрерывный): `GameTask::Put` (рисует в Put-буферы из Get-буферов) →
   `GraphicsSystem::Get/Process/Put` (рендер в отдельном потоке `OpenGLRenderer3D`; на macOS —
   в main thread, см. раздел «Кто где рисует (потоки рендера)» ниже).

Сцену переключают сообщения `GameTask::Action(e_GameTaskMessage_*)` — старт/стоп матча и меню-сцены.
Игровые объекты создаются через `ObjectFactory` и регистрируются в сценах (`scene3D->CreateSystemObjects`).

## Ввод (клавиатура + геймпад)

- **Клавиатура** — `HIDKeyboard` (`src/hid/keyboard.cpp`): читает `SDL_EVENT_KEY_*`
  из `UserEventManager` и раскладывает по `e_ButtonFunction` через `functionMapping`
  (дефолты в `defaultKeyIDs`, `src/gamedefines.hpp`).
- **Геймпад** — `HIDGamepad` (`src/hid/gamepad.cpp`) поверх SDL3 `SDL_Gamepad`
  (не сырые `SDL_Joystick`). `UserEventManager` (`src/managers/usereventmanager.cpp`)
  открывает геймпады через `SDL_OpenGamepad`, слушает `SDL_EVENT_GAMEPAD_*` и
  пишет в массивы по **семантическим индексам**: кнопки — `SDL_GAMEPAD_BUTTON_*`,
  оси — `SDL_GAMEPAD_AXIS_*` (стики −1..1, триггеры 0..1).
- **Стабильный ключ устройства** — `SDL_JoystickID` (из `event.gbutton.which`):
  раньше `which` использовался как индекс массива, что ломало Xbox Series
  (instance ID ≠ 0). Теперь `which → slot` через `GetSlotForJoystickID`.
- **Раскладка** — `controllerMapping[i]` (`e_ControllerButton` → физический ввод,
  `SDL_GAMEPAD_BUTTON_*` или ось со знаком) + `functionMapping` (`e_ButtonFunction`
  → `e_ControllerButton`). Два пресета `functionMapping`: **PES** (дефолт, A=пас,
  B=верхний пас, X=удар) и **FIFA** (A=пас, B=удар, X=навес). Переключатель PES/FIFA — на
  экране выбора сторон (`ControllerSelectPage`, per-gampad, циклически **LB/RB**,
  сохраняется в конфиг `input_gamepad_<id>_layout`). Переназначение под
  конкретное железо — в настройках геймпада (`GamepadMappingPage`,
  `Gui2CaptureJoy`).
- **Выбор сторон** (`ControllerSelectPage`) — каждый девайс выбирает сторону
  (Left/Right), затем подтверждает (**A** на геймпаде / **Enter** на клавиатуре);
  подтверждённые помечаются зелёным кругом с белой галочкой (рисуется вручную на
  `Image2D`). Переход к выбору команд — только когда **все** девайсы со стороной
  (−1/+1) подтвердили; в центре (0) ждать не нужно. **B** (геймпад) / **Esc**
  (клавиатура) — снять подтверждение (двухшаговый выход: сначала подтверждение,
  повторное нажатие — выход). Выбранные стороны сохраняются в
  `MenuTask::queuedFixture.sides` на время потока выбора матча и сбрасываются при
  входе в главное меню (`MainMenuPage` → `ClearControllerSetup()`).
- **GUI-навигация** — стик + крестовина одновременно: `guitask.cpp` складывает
  `SDL_GAMEPAD_AXIS_LEFTX/LEFTY` и `SDL_GAMEPAD_BUTTON_DPAD_*` в один вектор
  направления (знак крестовины совпадает со знаком оси LEFTY). В матче движение —
  только со стика. Подтверждение/назад: дефолты `joyButtonActivate/joyButtonEscape`
  = `SDL_GAMEPAD_BUTTON_SOUTH` (A) / `EAST` (B) — раньше были оба `1` (B), из-за
  чего с одним геймпадом B «выбирал», а назад не работал; переопределяются
  `SetEventJoyButtons` от геймпада, который ведёт меню.
- **Hot-plug** — `RefreshGamepads()` (`src/gamecontext.cpp`) вызывается из
  `GameTask::ProcessPhase`: пересобирает `controllers` по актуальным устройствам
  (ключ — `SDL_JoystickID`), возвращает признак изменения; при изменении
  `GameTask` перепривязывает human-геймеров (`match->UpdateControllerSetup()`),
  чтобы матч не читал удалённый `HIDGamepad`. `UserEventManager::RescanGamepads()`
  реагирует на `SDL_EVENT_GAMEPAD_ADDED/REMOVED`; эти события обрабатываются даже
  когда окно не в фокусе (`opengl_renderer3d.cpp`) — иначе пропущенное отключение
  навсегда оставляло «мёртвый» геймпад в списке (экран выбора сторон «зависал»).
- **Отключение геймпада в матче** — `GameTask` (раз в секунду) проверяет, что
  устройство игрока пропало из `controllers`. Если окно выбора сторон ещё не
  открыто (верхняя страница стека ≠ `ControllerSelect`): ставит матч на паузу
  (если не на паузе) и открывает выбор сторон **через `topPage->CreatePage(...)`**
  (как кнопка «controller select» в паузе) — так страница корректно встаёт в
  стек, а не накапливается в root. При подтверждении/закрытии окно `GoBack()`
  возвращает на паузу (или в матч, если `resumeOnClose` — паузу ставил сам
  `GameTask`, а не игрок).
- **Задел (не реализован):** simple-режим и геймпады без стиков — см.
  [[открытые-вопросы]].

## Рендер (OpenGL 3.2 core)

- Рендерер `OpenGLRenderer3D` (`src/systems/graphics/rendering/`) создаёт **core
  profile 3.2** контекст (`SDL_GL_CONTEXT_MAJOR_VERSION=3`, `MINOR=2`,
  `SDL_GL_CONTEXT_PROFILE_CORE`) — без fixed-function (нет `glBegin`/матричного
  стека/`glLight*`/client-side arrays). Контракт в `sdl_glfuncs.h`: deprecated-
  функции помечены `SDL_PROC_UNUSED` и не запрашиваются у драйвера (под core
  profile `SDL_GL_GetProcAddress` вернул бы NULL и лоадер упал бы).
- Весь рендер — через шейдеры (`#version 150`) и VAO/VBO: геометрия
  (`simple`/`zphase`), deferred-освещение (`ambient`+`lighting`, fullscreen-квад),
  пост-процесс (`postprocess`), 2D-оверлей (`overlay`). Light-типы: в игре всегда
  directional (`light.type == 0`), ветка point-light-сферы была dead code и убрана.
- Интерфейс `Renderer3D` очищен от мёртвых legacy-методов (`SetColor`,
  `SetTextureMode`, `RenderAABB`, `SetLight`, `SetClientTextureUnit`,
  `PushAttribute`/`PopAttribute`, `SetColorMask`, HDR-захват яркости) — они не
  вызывались игровым кодом и держали fixed-function GL.
- Шейдеры ещё `#version 150` (desktop GL), не `#version 300 es` — перевод на
  GLES (две ветки шейдеров) отложен, см. [[открытые-вопросы]].

### Кто где рисует (потоки рендера)

- **Windows/Linux:** `GraphicsSystem::Initialize` стартует рендер в отдельном
  потоке (`renderer3DTask->Run()`), окно/GL-контекст создаются сообщением
  `Renderer3DMessage_CreateContext` внутри этого потока, `SDL_PollEvent` тоже там.
- **macOS:** окно, GL-контекст и прокачка событий (AppKit) обязаны жить в main
  thread. Поэтому `GraphicsSystem::Initialize` на `__APPLE__` создаёт контекст
  синхронно на вызывающем (main) потоке и **не** стартует поток рендерера;
  `main()` запускает шедулер (`Run()`) во вспомогательном `boost::thread`, а цикл
  рендера `renderer3DTask->operator()()` — на main thread. Когда шедулер
  завершается, он шлёт рендер-циклу `Message_Shutdown`; `GraphicsSystem::Exit` на
  macOS поток рендерера не останавливает (его нет).
- **2D-оверлей-текстуры (GUI) создаются асинхронно.** `Texture::CreateTextureAsync`
  (путь `GraphicsOverlay2D::OnLoad`) шлёт `Renderer3DMessage_CreateTexture` без
  `Wait()`; GL-id записывается обратно в ресурс текстуры прямо в сообщении, на
  рендер-потоке. `Renderer3DMessage_UpdateTexture` тоже резолвит id на рендер-потоке
  из ресурса (FIFO очереди гарантирует, что create выполнится раньше update).
  Раньше каждый `CreateImage2D` блокировал гейм-поток на один кадр рендера
  (~10–30 мс с vsync), а страница выбора команд создавала ~70 текстур → загрузка
  экрана занимала ~0.7–1 с; стало ~40 мс. Текстуры геометрии/поля/теней
  (match-loading, скрыто экраном загрузки) остались на синхронном
  `Texture::CreateTexture`.

## Инварианты проекта

- **Один `time_ms`** — глобальный extern (`src/gamedefines.hpp:16`). Источник истины —
  `EnvironmentManager::GetTime_ms()`; параллельное время не заводить. Исключение: симуляция
  матча (`Match::Process`) отвязана от реальных часов — время продвигается фиксированным шагом
  10 мс за вызов (`actualTime_ms += 10`), что делает headless-прогоны детерминированными.
- **Get/Process/Put и мьютексы.** Игровая логика и рендер в разных потоках; границы защищают
  `matchPutBufferMutex`, `matchLifetimeMutex`, `getPhaseMutex`. Ломать блокировки — сегфолт на выходе.
- **Boost-идиомы**: `boost::intrusive_ptr`/`boost::shared_ptr`, `boost::signals2`, `boost::thread`.
- **Физика (ODE) не компилируется** для игры; правки в `src/systems/physics/*` не соберутся.

## Headless-инструменты

- **Игровой контекст вынесен** в `src/gamecontext.*` (глобальные переменные и геттеры,
  которые раньше жили в `main.cpp`): `scene2D`, `scene3D`, `graphicsSystem`, `audioSystem`,
  `db`, `config`, `menuTask`, `gameTask`, pilons, `controllers`. Инициализация — `InitGameContext()`,
  очистка — `ShutdownGameContext()`. Это позволяет отдельным бинарникам линковать контекст
  без `main.cpp` (в котором `main()`).
- **`tools/determinism`** — headless-раннер детерминизма: `run` (печатает SHA-1 состояния
  матча после 5000 тиков с сидом 42) и `check <hash>` (сравнивает с эталоном, код выхода 0/1).
  В начале ФИКСИРУЕТ ключи конфига (`graphics3d_renderer=mock`, `audio_renderer=mock`,
  `match_difficulty=0.8`, `match_duration=1.0`), так что хэш не зависит от `football.config`.
  Эталоны — на платформу: `reference.txt` (Windows x86), `reference-windows-x64.txt`,
  `reference-linux.txt` (последние два — см. [[открытые-вопросы]]). Использует
  `EnvState`-сериализацию (`src/defines.hpp`) и `Match::ProcessState` (см. [[матч]]).
- **`MockRenderer3D`** (`src/systems/graphics/rendering/mock_renderer3d.hpp`) — заглушка рендерера
  без окна/GL-контекста; включается ключом конфига `graphics3d_renderer=mock`. Игра по умолчанию
  использует OpenGL, mock — только для headless-тулов.

## Сборка

- **Сборка**: CMake 3.16+, C++17; единый статический `blunted2` (из бывших OBJECT-библиотек) +
  игровые библиотеки; SDL3-таргеты `SDL3::SDL3`, `SDL3_image::SDL3_image`, `SDL3_ttf::SDL3_ttf`.
  SDL_gfx не используется вовсе (в vcpkg его нет; заменён на `SDL_ScaleSurface`). Физика (ODE)
  по-прежнему не собирается. **Windows**: зависимости — vcpkg в manifest mode (`vcpkg.json` в корне,
  триплет `x86-windows`, генератор Win32; отдельный `vcpkg install` не нужен). `find_package`
  в основном модульный на всех платформах (FindOpenAL/FindSQLite3 находят и системные, и vcpkg
  библиотеки через prefix path; у SDL3* нет Find-модулей — модульный вызов сам откатывается на
  CONFIG-файлы). Платформенными остаются только две ветки: **Boost** (CONFIG под vcpkg; на
  не-Windows `Boost_NO_BOOST_CMAKE=ON` + модульный `find_package(Boost COMPONENTS thread filesystem)`
  — системный Boost b2 не даёт компонентных конфигов; `Boost.System` header-only с 1.69, не
  линкуется) и **SQLite** (`unofficial::sqlite3::sqlite3` под vcpkg, `SQLite::SQLite3` на не-Windows).
  `data/` копируется рядом с exe автоматически (POST_BUILD), игра-бинарник можно запускать прямо из
  каталога сборки. Windows-игра — GUI (`WIN32`-подсистема) через опцию
  `GAMEPLAYFOOTBALL_WINDOWS_SUBSYSTEM` (по умолчанию ON; OFF — консоль для дебага) со своей
  WinMain-заглушкой в `src/main.cpp` (SDL3 не даёт SDLmain). Linux: игровые
  статические библиотеки имеют циклические ссылки (`hidlib` ↔ `gamecontextlib`) — на GNU ld
  они линкуются через `-Wl,--start-group/-end-group` (`CMakeLists.txt`, только `UNIX AND NOT APPLE`;
  MSVC/ld64 терпят плоский порядок).
- **Проверенные версии зависимостей** (версии пинит каждая платформа по-своему — при миграции
  сверять поведение, пример: семантические имена SDL3-кнопок A/B-алиасы vs SOUTH/EAST есть не во
  всех версиях):
  - vcpkg `x86-windows`: sdl3 3.4.12, sdl3-image 3.4.4, sdl3-ttf 3.2.2, openal-soft 1.25.1,
    boost 1.91.0, sqlite3 3.53.4;
  - Ubuntu 26.04: libsdl3-dev 3.4.2, libsdl3-image-dev 3.4.0, libsdl3-ttf-dev 3.2.2,
    libopenal-dev 1.25.1, boost 1.90.0, libsqlite3-dev 3.46.1;
  - brew (MacBook Air M2, 2026-08-13): sdl3 3.4.14, sdl3_image, sdl3_ttf, boost 1.90, openal-soft.
- **Headless-звук**: `determinism_runner` ставит `audio_renderer=mock` — `MockAudioRenderer`
  (`src/systems/audio/rendering/mock_audiorenderer.hpp`) реализует `AudioRenderer` no-op'ами,
  т.к. на headless-машинах может не быть аудио-устройства, и `OpenALRenderer::CreateContext`
  падает фатально.

## Что пробовали и отвергли

- **Google Brain (ветка `google_brain`)** — RL-обвязка для исследования; выброшены меню, звук, HUD.
  Цель форка — вернуть их и собрать игру на многих платформах. Не вливать ветку целиком.
- **Windows-линия (ветка `windows`)** — отдельная ветка сборки; нужные MSVC-правки
  (NOMINMAX, `std::vector` вместо VLA, сигнатура `main(int, char**)`) перенесены в `master`,
  ветку целиком не вливать. Сборка подтверждена end-to-end на MSVC (VS2022 Build Tools,
  vcpkg `x86-windows`, см. `AGENTS.md`).
- **Вендорный SQLite** — убран в `68159a2`, сборка использует системный пакет.
