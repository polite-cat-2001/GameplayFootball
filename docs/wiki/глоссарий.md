# Глоссарий

Словарь проекта. Термины читаются и дописываются здесь, а не в корневом `CONTEXT.md` (он — только
указатель на эту страницу). Термин берётся отсюда для заголовков задач и формулировок гипотез.

Формат: `**Термин**:` + определение + `_Avoid_:` + список запрещённых синонимов. К термину
добавляется вики-ссылка на страницу подсистемы (двойные квадратные скобки, имя файла без `.md`),
если такая страница есть.

## Термины

**Match**:
Полная симуляция одного футбольного матча: команды, игроки, мяч, судьи, AI. Класс `Match`
в `src/onthepitch/match.hpp`. Синоним каталога — `onthepitch`. Подробнее — [[матч]].
_Avoid_: «симулятор», «поле», «игра»

**onthepitch**:
Имя каталога `src/onthepitch` — вся симуляция матча. Это не отдельное понятие, а способ
называть подсистему Match по имени её каталога. Подробнее — [[матч]].
_Avoid_: «on-the-pitch», «онтепитч»

**ElizaController**:
AI-контроллер ботового игрока (`src/onthepitch/player/controller/elizacontroller.hpp`). Назван
в честь классической ELIZA, к современным LLM отношения не имеет. Управляет игроком без человека:
стратегии вне мяча, ментальный образ, выбор паса. Подробнее — [[матч]].
_Avoid_: «нейросеть», «бот», «Eliza», «Элиза»

**Blunted2**:
Имя движка, на котором написана игра; исходники в самом репозитории (`src/base`,
`src/types`, `src/scene`, `src/systems`, `src/managers`, `src/framework`). Был вынесен из
GameplayFootball и обновлён. Подробнее — [[архитектура]].
_Avoid_: «движок GameplayFootball», «нативный движок»

**Get/Process/Put**:
Три фазы жизненного цикла задач и систем: Get (чтение ввода), Process (симуляция),
Put (вывод в буферы для другого потока). Есть у `GameTask`, `MenuTask`, систем.
Подробнее — [[архитектура]].
_Avoid_: «подготовка/симуляция/отрисовка» без объяснения, что это фазы конвейера

**MatchData**:
Данные для старта матча: команды, составы, комплекты — подготавливаются меню и передаются
в `Match` сообщением `StartMatch`. Подробнее — [[база-данных]].
_Avoid_: «данные матча» в одном слове «матчдата»

**PES-раскладка** (PES-like):
Единственная раскладка `functionMapping` геймпада: A = короткий пас, B = верхний пас,
X = удар, Y = длинный пас (стиль PES6). Пресет задан в `GetDefaultFunctionMapping`
(`src/hid/gamepad.cpp`); выбора пресетов нет. Подробнее — [[архитектура]].
_Avoid_: «стиль PES», «FIFA-раскладка»

**Hot-plug**:
Подключение/отключение геймпада на лету без перезапуска игры. Стабильный ключ устройства —
`SDL_JoystickID`; `RefreshGamepads()` пересобирает список контроллеров в game-потоке. Отключение
геймпада игрока в матче ставит паузу и открывает выбор сторон. Подробнее — [[архитектура]].
_Avoid_: «горячая замена», «подключение во время игры» (можно, но термин — hot-plug)

**Канон** (canon):
Единый JSON-набор данных на TM-id, источник истины для обеих игр (GF и football_collection).
Без GF-специфики: `base_stat`, `profile_xml`, формации считают конвертеры. Подробнее —
[[данные-из-transfermarkt]].
_Avoid_: «мастер-база», «главный JSON» (двухсловный пересказ)

**TM-id**:
Строковый идентификатор сущности на transfermarkt.com (игрок `8198`, клуб `131`, сборная `3377`,
лига `ES1`). Единый ключ всех сущностей канона.
_Avoid_: «айди», «идентификатор Transfermarkt» без сокращения TM

**Tier-1**:
Исторический охват **первого релиза** данных: топ-5 лиг + их вторые дивизионы + топ-20 сборных
(~220 команд). Прод уже шире — полный краул 2026-09-01 покрыл 106 стран / 279 лиг / 4406 клубов
(см. [[открытые-вопросы]]). Расширение — по мере надобности.
_Avoid_: «все лиги сразу»

**Тактическая схема** (tactical scheme):
Набор из одиннадцати ролей (`e_PlayerRole`) и их позиций — построение команды
(4-4-2, 4-3-3, 4-2-3-1, 3-5-2, 5-3-2, 4-5-1). Захардкоженный список — в
`src/menu/tacticschemes.cpp` (`TacticalScheme`), выбор — в разделе **Tactics** экрана плана
игры; назначение позиций игрокам — венгерским методом. Подробнее — [[матч]].
_Avoid_: «тактика» (это весь раздел Tactics, а не построение), «схема игры» без уточнения

**Формация** (formation):
Конкретные роли/позиции состава в `TeamData::formation` / `Team::runtimeFormation`
(`FormationEntry`). В пре-матче — стартовый XI, в матче — рантайм-формация (её меняют замены
и тактические схемы). Синоним тактической схемы, когда речь о конкретном построении команды.
Подробнее — [[матч]].
_Avoid_: «расстановка» (можно, но термин — формация)

**Кит** (kit):
PNG 1024×1024 с UV-раскладкой формы команды в GF (торс = color1, рукава/шорты/носки = color2).
Генерируется по `template_kit.png`. Подробнее — [[данные-из-transfermarkt]].
_Avoid_: «форма», «текстура формы» (можно, но термин — кит/kit)

**Resume-кэш**:
Локальное хранилище уже собранных данных скрейпера (SQLite), чтобы краул можно было прерывать
и продолжать без повторных запросов к TM.
_Avoid_: «кэш прогресса», «сохранение краула»

**Пайплайн данных** (data pipeline):
Совокупность звеньев-репозиториев, по которым данные Transfermarkt доходят до игры:
api → скрейпер → генераторы → конвертер (tm-gf-import) → игровой каталог данных. Единый договор —
[[пайплайн-данных]].
_Avoid_: «конвейер данных» без уточнения, что это сводный договор (не только скрейпер)

**Снимок данных** (data snapshot):
Один неизменяемый срез данных на выходе полного прогона: канон-JSON + картинки + спеки генераторов,
далее — игровая БД. Имеет `snapshot_id` (дата среза + git-хаши инструментов). Подробнее —
[[пайплайн-данных]].
_Avoid_: «свежие данные», «новая база» без версии

**Манифест данных** (data manifest):
Файл `manifest.json` рядом с игровой БД: `schema_version`, `data_version`, `snapshot_id`,
coverage и sha256. Пишет конвертер (`tm-gf-import`). Подробнее — [[пайплайн-данных]].
_Avoid_: «файл версии», «версия базы» без уточнения уровня (schema vs data)

**Curl** (крученый удар):
Удар с намеренной кривизной траектории (усиленное вращение мяча, эффект Магнуса). В игре —
модификатор удара; расчёт траектории — общий ударный код, годный и для ИИ. Подробнее — [[матч]].
_Avoid_: «кручёный пас», «финт»

**Chip** (черпачок):
Навесной удар по высокой параболе через соперника (в отличие от низового/плоского). В игре —
модификатор удара. Подробнее — [[матч]].
_Avoid_: «навес» (это `LongPass`/подача), «плоский верхний»

**Attacking run** (забегание):
Целенаправленный рывок партнёра вперёд, инициируемый игроком (кнопкой) или тактикой ИИ;
живёт ограниченное время (`ApplyAttackingRun`, 4 с). Подробнее — [[матч]].
_Avoid_: «забег», «рывок»

**Knock-on** (проброс):
Ускоренное проталкивание мяча вперёд при касании (вектор касания ×1.35, модификатор
`e_PlayerCommandModifier_KnockOn`): игрок отпускает мяч дальше обычного и бежит за ним.
_Avoid_: «пинок», «толчок»

**Super-cancel** (супер-кансел):
Полное снятие автодоводки движения («магнита»): сырой стик перебивает AI-подмешивание
(`autoBias`). Доступен, когда мяч не под контролем. Подробнее — [[матч]].
_Avoid_: «отмена»/«кансел» без уточнения, что снимается автодоводка

**Стоп-на-месте** (planted):
Остановка designated possession игрока при удержании кнопки, даже с отклонённым стиком.
Подробнее — [[матч]].
_Avoid_: «тормоз», «stand still»

**Раздача вратаря** (keeper distribution):
Набор действий вратаря с мячом в руках: вброс руками (тап — раскат низом ближнему, удержание —
бросок верхом дальнему), выбивание ногой (в центр / по стику), «в ноги» (мяч к своим ногам,
вратарь становится полевым). Подробнее — [[матч]].
_Avoid_: «пас вратаря» без уточнения типа раздачи

**Презентация стандарта** (set-piece presentation):
Камера, прицел и спец-ввод, которые видит управляющий человек при розыгрыше стандарта
(пенальти, штрафной, угловой, аут, от ворот, кикофф). Существует только для человека: ИИ-тайкер
через неё не идёт и зовёт общий расчёт удара напрямую. Носитель — `SetPiecePresentation`
(владеет `Match`), роль участия — `e_SetPieceRole`: `Kicker`, `Keeper` или `None` — считается по
локальному управляемому игроку. Подробнее — [[матч]].
_Avoid_: «UI стандарта», «оверлей стандарта»

**Прицел стандарта** (set-piece aim):
Направление подачи, которое тайкер-человек наводит стиком при розыгрыше стандарта; камера
стандарта едет за ним. Отдельно от 2D-ретикла пенальти. Подробнее — [[матч]].
_Avoid_: «прицел удара» (это про обычные удары), «наведение»

**Навес** (cross):
Верховая подача в штрафную или вперёд по полю — вид подачи на стандарте (кнопка верхнего паса).
Высоту дуги задаёт стик вверх-вниз, дальность — удержание. Не путать с черпачком: черпачок —
удар, а не подача. Подробнее — [[матч]].
_Avoid_: «лонгбол», «подача сверху» без уточнения

**Пас на ход низом** (through ground pass):
Низовая передача в свободную зону на ход партнёру — вид подачи штрафного. Не навес.
Подробнее — [[матч]].
_Avoid_: «проникающий пас»

**Стенка** (defensive wall):
Ряд полевых игроков обороняющейся команды при штрафном, выстроенный на 9.15 м от мяча на линии
к своим воротам (в сторону ближней штанги). Число игроков — от дистанции до ворот; стенка
автоматически прыгает под летящий мяч. Остаётся под управлением ИИ. Подробнее — [[матч]].
_Avoid_: «барьер», «частокол»

**Прыжок стенки** (wall jump):
Автоматический подъём всех игроков стенки под летящий мяч при штрафном. Триггер высото-независимый
(по времени подлёта, а не по высоте мяча); поза и подъём тела задаются анимацией, а не кодом.
Подробнее — [[матч]].
_Avoid_: «блок», «отбивание»

**Игра за вратаря** (play as keeper):
Управление вратарём человеком в двух режимах: мяч в руках (бег по штрафной с жёстким клэмпом
и раздача) и полевой режим (мяч у ног). Управление включается на ловле и на обратном пасе; при
потере мяча вратарь возвращается в ворота, управление уходит полевому игроку. Подробнее — [[матч]].
_Avoid_: «режим вратаря», «голкипер-контроль»

**Слой вратаря** (keeper layer):
GF-native слой поверх существующего владения: перечисление `e_KeeperState`
(`None`/`Hands`/`Outfield`/`Returning`) и чистый расчёт `keeperlogic` (`src/onthepitch/keeper/`),
владеется `Match` рядом с `ballRetainer`; владение по-прежнему идёт только через
`SetBallRetainer`. Не путать с «игрой за вратаря» — это механика; слой — её носитель.
Подробнее — [[матч]].
_Avoid_: «система вратаря», «модуль голкипера», «keeper-контроллер»

**Зона нырка** (dive zone):
Одна из семи зон, в которую вратарь-ИИ бросается на пенальти: `LOW_L`/`MID_L`/`HIGH_L`/`LOW_R`/
`MID_R`/`HIGH_R`/`CENTER` (`e_KeeperDiveZone`). Сторона — относительно экрана бьющего; по высоте три
полосы (низ/середина/верх); `CENTER` — центральная реакция. Подробнее — [[матч]].
_Avoid_: «квадрант», «сторона прыжка»

**Оборона пенальти** (penalty defense):
Поведение вратаря защищающейся команды на пенальти: остаётся под ИИ, дрейфует вдоль линии по стику
человека и защёлкивает зону нырка в момент касания мяча бьющим. Намерение человека — сайд-канал
одного пути вратаря. Подробнее — [[матч]].
_Avoid_: «пенальти-режим вратаря», «управляемый вратарь на пенальти»

**Автовынос** (auto-release):
Принудительный вынос мяча вратарём в центр по истечении правила 6 секунд удержания; после него
управление отдаётся ближайшему к точке приземления партнёру. Подробнее — [[матч]].
_Avoid_: «принудительный пас», «таймаут вратаря»

**Хэндофф** (handoff):
Передача управления на партнёра сразу после раздачи вратаря — на адресата мяча, а при автовыносе
на ближайшего к точке приземления. Не путать с автопереключением игрока. Подробнее — [[матч]].
_Avoid_: «передача управления» без уточнения, что речь о вратаре

**Designated-игрок** (designated possession player):
«Назначенный главный игрок у мяча»: `designatedPossessionPlayer` у `Match` (один на матч) и
`designatedTeamPossessionPlayer` у `Team` (по одному на команду). На нём завязаны подсветка,
HUD и камера, он же — цель автоподстановки управления. Отличается от **выбранного игрока**
(`selectedPlayerID` у `HumanGamer`): designated — кандидат от команды, выбранный — за кого
реально играет человек. На стандарте designated отыгрывающей команды равен **бьющему**.
Подробнее — [[матч]].
_Avoid_: «главный игрок», «главный у мяча», «владетель» (термин — designated)

**Бьющий** (set-piece taker):
Фактический исполнитель стандарта (`RefereeBuffer.taker`, разрешённый
`TeamAIController::PrepareSetPiece` для пенальти/штрафного/углового; для аута/кикоффа — ближайший).
На время стандарта designated отыгрывающей команды указывает на бьющего. Может быть сменён через
меню смены бьющего. Подробнее — [[матч]].
_Avoid_: «исполнитель стандарта», «подающий» без уточнения типа стандарта

**Меню смены бьющего** (set-piece taker menu):
Экран со списком активных игроков команды (включая вратаря), доступный бьющему-человеку на
стандарте по кнопке Share / `Tab`. Выбор меняет фактического бьющего (новый встаёт за мяч,
старый уходит в строй); управление остаётся за открывшим меню. Подробнее — [[матч]].
_Avoid_: «меню подающего», «выбор пенальтиста» (последнее — план-роль, не фактический бьющий)

**Разбег бьющего** (set-piece kicker run-up):
Подход бьющего к мячу перед ударом на стандарте. Есть только у **пенальти и штрафного**: бьющий
стартует за мячом и подходит к нему, а не бьёт с места вплотную. Разбег ведёт обычная система
движения (спринт-команда к мячу); сам удар придержан, пока бьющий не добежит, после чего срабатывает
штатный удар и клип удара доводит ногу до касания. Дистанция старта задаётся не отдельным
root-motion-клипом, а смещением мяча на кадре касания выбранного клипа удара. У углового и удара от
ворот разбега нет. Подробнее — [[матч]].
_Avoid_: «забег», «рунап»

**Менеджер** (manager):
Роль игрока в режиме карьеры: ведёт трансферы, бюджет, академию и состав клуба. Единый термин
для режима «карьера менеджера» (спецификация
[#54](https://github.com/polite-cat-2001/GameplayFootball/issues/54)); в сейве карьеры —
отдельная сущность (имя/национальность/репутация/доверие), не `coach_id` (который есть только
в каноне, не в игровой БД).
_Avoid_: «тренер», «коуч», «coach»

**Доверие совета** (board trust):
Клуб-локальная метрика карьеры (%). Растёт/падает от выполнения целей; ниже порога — увольнение
менеджера. При смене клуба сбрасывается и сеется из репутации менеджера + статуса нового клуба.
_Avoid_: «доверие руководства» без уточнения, «доверие фанатов» (это не то же самое)

**Подписчики** (subscribers):
Долгосрочный счётчик популярности клуба (N). Растёт от наград/трофеев/звёздных подписаний/OVR;
буст наград затухает, без успехов медленно деградирует. Драйвит продажи футболок и базовый matchday.
_Avoid_: «популярность клуба» (термин — подписчики), «фанаты» в смысле числа

**Удовлетворённость фанатов** (fan satisfaction):
Клубная метрика карьеры (%), колеблется от результатов/целей/выбора спонсора. Влияет только на
деньги (множитель matchday + рычаг спонсора); на увольнение напрямую не влияет. Не путать с доверием
совета.
_Avoid_: «доверие фанатов», «реакция фанатов» без уточнения, что это про деньги

**Стоимость клуба** (club value):
Производная метрика карьеры = сумма трансферной стоимости всех игроков клуба + баланс. Используется
долгосрочными финансовыми целями.
_Avoid_: «цена клуба», «капитализация»

**Задолженность по зарплате** (salary arrears):
Ситуация, когда на дату списания зарплат (30-е) баланса не хватает и часть зарплаты остаётся
невыплаченной. Ведёт к падению доверия совета и недовольству игроков (v1 — нарратив; последствия —
v2/v3).
_Avoid_: «недоимка», «долг по зарплате» (термин — задолженность по зарплате)

**Цели** (objectives):
Задачи, спускаемые руководством (менеджер их не выбирает): 12 слотов = 4 категории (финансовые /
имиджевые / спортивные / академия) × 3 срочности (кратко-/средне-/долгосрочные). Успех/провал даёт
дельты в доверие совета, удовлетворённость фанатов, бюджет след. сезона и репутацию менеджера.
_Avoid_: «задачи сезона» без уточнения категорий/срочностей

**Травма** (injury):
Состояние игрока из condition-модели карьеры; возникает в обычном `Match`. Два типа: некритичная
(снижена скорость + отключён спринт/knock-on, игрок продолжает) и критичная (пауза → план игры →
принудительная замена; нет замен — в меньшинстве). Обе дают восстановление после матча.
_Avoid_: «повреждение», «увечье»

**Серия пенальти** (penalty shootout):
Фаза `e_MatchPhase_Penalties`: решает ничейный кубковый матч (5+5, затем sudden death), переиспользуя
механику пенальти; работает с ИИ и локальным 2P. Доп. время в движке уже есть.
_Avoid_: «пенальти-серия» без уточнения, что это фаза матча

**Коэффициент клуба** (club coefficient):
Число очков клуба в континентальных турнирах (W/D/L + бонус стадий) за 5 сезонов, без учёта силы
соперника. Определяет посев клуба. v2.
_Avoid_: «рейтинг клуба» (термин — коэффициент)

**Коэффициент страны** (country coefficient):
Среднее коэффициентов клубов страны; определяет квоту страны (сколько клубов и с какой стадии) в
континентальных турнирах. v2.
_Avoid_: «рейтинг страны»

**Рейтинг сборной** (national-team ranking):
Elo-рейтинг сборной: `P + важность×(результат−ожидание)`, со силой соперника; определяет посев
турниров сборных. На квоты клубов не влияет. v2.
_Avoid_: «рейтинг ФИФА» без уточнения, что это Elo

**Уважение** (respect):
Per-player метрика отношения игрока к менеджеру (%). Драйверы: задолженность по зарплате, результаты,
игровое время относительно уровня состава, продажа звезды. Эффекты (пороговые): продление контракта,
отказ играть/запрос трансфера/уход, бонус к перформансу. Агрегат — «уважение команды» (среднее). v3.
_Avoid_: «мораль», «лояльность»

**Рейтинг** (OVR):
Показываемая сила игрока = `base_stat × 100` (с возрастной поправкой `CalculateStat`). Единое число
для целей, известности, продаж футболок и гейтинга вакансий. Отдельного атрибута OVR нет. Подробнее —
[[база-данных]].
_Avoid_: «общий рейтинг» без уточнения, что это `base_stat×100`

**Стоимость игрока** (market value):
Динамичная трансферная стоимость игрока (€) из данных (`players.market_value`, схема v4); привязана к
силе лог-шкалой (`base_stat` = лог от стоимости) и меняется в карьере вместе с силой.
_Avoid_: «цена игрока» (термин — стоимость), «стоимость» без уточнения (есть ещё стоимость клуба)

**Сила клуба** (club strength):
Композит для гейтинга вакансий: сумма `market_value` состава + уровень дивизиона + средний OVR.
Отличается от «стоимости клуба» (та — Σ стоимости + баланс).
_Avoid_: «уровень клуба» без уточнения состава

**Потенциал** (potential):
Жёсткий потолок OVR игрока (своё число на игрока, `players.potential`, схема v4). Выше игрок не
растёт; показывается диапазоном в скаутинге.
_Avoid_: «потенция», «потолок» без уточнения

**Привычка к позиции** (position familiarity):
Освоенность полевой позиции 0–100 %. Растёт игрой на этой позиции или тренировкой; низкая привычка —
штраф к статам в матче. Переучившись, игрок получает шаблоны новой позиции.
_Avoid_: «знакомство с позицией»

**Игровая роль** (player role):
Шаблон развития, привязанный к позиции (Вратарь-либеро, Плеймейкер, Лис у ворот…): задаёт набор
ключевых статов, которые качает план развития. 21 роль + общие «Баланс»/«Динамический». Только
развитие, на поведение на поле не влияет. Не путать с `e_PlayerRole` (позиция).
_Avoid_: «амплуа» (термин — игровая роль), «стиль игры» (про тактику)

**Завершение карьеры** (retirement):
Уход игрока по возрастной кривой: выше рейтинг — позже; вратари позже защитников → полузащитников →
нападающих. Контракт расторгается, игрок удаляется из состава/свободных агентов.
_Avoid_: «пенсия», «конец карьеры» (термин — завершение карьеры)

**Событие** (career event):
Момент событийного времени карьеры. Два вида: **halt** (фикстура, окно трансферов, отчёт скаута,
переход сезона, дедлайн цели, увольнение, ежемесячная дата — симуляция останавливается) и **не-halt**
(матчи соперников — резолвятся «вокруг»). Следующее ищется опросом источников за ближайшую дату.
_Avoid_: «тик», «ход» без уточнения, что это карьерное время

**Журнал команд** (command journal):
Append-only список решений игрока за карьеру (трансфер, выбор состава, play/sim) для replay: тот же
`seed` + тот же журнал воспроизводят карьеру; сыгранный 3D-матч подставляет записанный исход, quick-sim
пересчитывается. Механизм детерминизма карьеры.
_Avoid_: «лог действий» без уточнения, что это replay

**Исход матча** (MatchOutcome):
Единый контракт результата фикстуры, который и сыгранный 3D `Match`, и quick-sim возвращают в карьеру:
счёт + по игроку обеих команд минуты/голы/ассисты/карточки/итоговая усталость/травма. Карьера применяет
его через `applyOutcome()`; сыгранный матч записывается в сейв как снимок исхода.
_Avoid_: «результат матча» без уточнения, что это контракт состава полей

**Усталость** (fatigue):
Персистентная доля состояния игрока (0–100 %, 100 = свежий). В матче — `fatigueFactorInv`; карьера
пишет вход (fatigue/100) и читает выход (×100), восстанавливается по карьерным дням.
_Avoid_: «форма», «выносливость» (термин — усталость)

**Дисквалификация** (suspension):
Персистентный счётчик банов игрока, раздельно для лиги и кубка: прямая красная = бан 1 матч в том
турнире, где получена. Декремент за каждый отбытый матч.
_Avoid_: «бан» без уточнения турнира, «удаление» (это про конкретную красную)

**Сейв карьеры** (career save):
Один pretty-printed JSON-файл с мутабельным состоянием карьеры, отдельный от SQLite: менеджер, клубы,
игроки (атрибуты/контракты/condition), сезоны/турниры, финансы, цели, метрики, `seed`, журнал команд
и записанные исходы. `version` + отказ на несовпадении, без миграций в v1.
_Avoid_: «сохранение карьеры» без уточнения, что это JSON

**Скаут** (scout):
Сотрудник (1–3), разведывает взрослых игроков и находит, кого подписать. Два параметра: **скорость**
(N дней до точного рейтинга) и **качество поиска** (насколько подходящих, нужных на данный момент и
выгодных по «цена/качество» игроков находит). «Поручить скауту разведку» по игроку → через N дней он
в отчёте скаута с точным рейтингом. Самостоятельный просмотр рынка — с фиксированной вилкой атрибутов.
_Avoid_: «разведчик», «агент» (агент — сторона игрока в переговорах)

**Молодёжный скаут** (youth scout):
Отдельная должность (не из 1–3 скаутов). Назначается в регион и периодически присылает отчёт с
юниорами (младше 16, текущий рейтинг + потенциал). Качество определяет средний уровень находимых
юниоров.
_Avoid_: «скаут академии» без уточнения, что это отдельная должность

**Академия** (academy):
Юношеский состав менеджера: подписанные юниоры (младше 16) на молодёжной зарплате, авто-рост к
потенциалу, промоушен в основу в 16 лет. Только у менеджера; соперники — авто-intake.
_Avoid_: «юношеская команда» без уточнения механики

**Юниор** (youth player):
Игрок академии младше 16 лет (текущий рейтинг + потенциал). Подписывается на молодёжную зарплату,
растёт к потенциалу; в 16 лет может быть промоушен в основу.
_Avoid_: «молодой игрок» (это про возраст в основной команде), «кадета»
