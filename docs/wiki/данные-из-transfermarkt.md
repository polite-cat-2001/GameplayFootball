# Данные из Transfermarkt

## Что это

Конвейер поставки актуальных футбольных данных (составы, клубы, сборные, стоимости) из
Transfermarkt в две игры: GameplayFootball и football_collection. Источник — форк
[transfermarkt-api](https://github.com/packee-dev/transfermarkt-api) (FastAPI-обёртка над
скрейпингом transfermarkt.com, дополнена сборными и тренерами). Единый **канонический JSON на
TM-id** — источник истины; конвертеры производят из него GF SQLite и Flutter-assets.

Ветка разработки: `develop` (фичи — из `squads-update`). См. также [[база-данных]].

## Схема конвейера

```
transfermarkt.com
   │  (HTML + внутренние JSON-API)
   ▼
transfermarkt-api  (локальный FastAPI, :8000)
   │  HTML 1.5 rps / CDN 10 rps (probe 2026-08-29), resume-кэш, curl_cffi
   ▼
скрейпер (transfermarkt_scrapper)
   │
   ▼
канон-JSON на TM-id  (единый источник истины)
   ├──► конвертер 1 → GF SQLite (teams/players/leagues + киты, логотипы)
   └──► конвертер 2 → Flutter assets (prepared_tm_*.json) для football_collection
```

Скрейпер ходит **не на transfermarkt напрямую**, а на локальный transfermarkt-api, который уже
скрейпит TM. Лимит ≤2 запроса/сек к TM обязателен — при частых запросах TM банит IP надолго.

## Канонический формат

Ключ всех сущностей — строковый **TM-id**. Никакой GF-специфики в каноне: `base_stat`,
`profile_xml`, формации, цвета в формате GF считает конвертер.

```
data/
  meta.json                          # version, snapshot_date, tm_season, counts
  competitions.json                  # лиги/кубки: id, name, type, country{id,name}, tier, logo
  clubs.json                         # id, name, colors[] (HEX), stadium{name,seats}, league_id,
                                     #   logo, founded_on
  national_teams.json                # id, name, coach_id, flag, emblem
  players.json                       # id, name, first_name, last_name, birth_date, height, weight,
                                     #   foot, citizenship[], position{main,other}, club_id,
                                     #   national_team_id, shirt_number, market_value,
                                     #   max_market_value, outfitter, is_retired
  players_market_value.json          # id, history[{age,date,clubId,clubName,marketValue}]
  coaches.json                       # id, name, citizenship, current_club_id
```

### Источники полей (проверено живыми запросами 2026-08-29)

| Поле канона | Источник | Примечание |
|---|---|---|
| `role`, `height`, `foot`, `birth_date`, `marketValue`, `citizenship`, `position` | `GET /clubs/{id}/players` | состав клуба — 1 запрос на команду |
| `national_team_id` | `GET /national-teams/{id}/players` | **только здесь** — профиль игрока сборную не даёт |
| `shirt_number` (в сборной) | `GET /national-teams/{id}/players` → `shirtNumber` | поле добавлено в форк |
| `coach_id` | прямой парсинг `/mitarbeiter/verein/{id}` | **API сборных тренера не отдаёт** |
| `colors`, `stadium`, `league` | `GET /clubs/{id}/profile` | |
| `max_market_value` | `GET /players/{id}/market_value` (история) | нужен только коллекционке |
| `weight` | **отсутствует в TM** | эвристика в конвертере (рост + позиция) |
| `shortname` (3 буквы для GF) | **отсутствует в TM** | выводить в конвертере |

### Стратегия сбора

Основной источник — **состав клуба** (`clubs/{id}/players`): для ~220 команд Tier-1 это ~220
запросов вместо одного на игрока. Индивидуальные профили (`/players/{id}/profile`) — точечно:
`outfitter`, `imageUrl`, multi-позиции для игроков, нужных коллекционке. История стоимости —
отдельный запрос на игрока, только для коллекционки.

## Маппинг в GF SQLite

| GF-поле | Источник / логика |
|---|---|
| `players.role` | маппинг TM-позиции → GF-токен: Centre-Forward→ST, Left Winger→AM L, Defensive Midfield→DM, Left-Back→D/WB L…; `position.other` — доп. позиции через `/` |
| `players.base_stat` | формула из `market_value` (лог → 0..1), возрастной корректир делает `CalculateStat` в игре |
| `players.profile_xml` | 22 стата по роли, тот же алгоритм, что в GF (`GetDefaultProfile`, `src/utils.cpp`); исследование-прототип с калибровкой по FIFA — см. «Калибровка 22 статов по FIFA» на этой странице |
| `players.height` | см → м (1.87) |
| `players.weight` | эвристика (рост + позиция), TM вес не даёт |
| `players.formationorder` | стартовые 11 (лучшие по `base_stat` + роль), слот формации `p(i+1)` ↔ игрок `[i]` |
| `players.nationalteam_id` | из состава сборной; `nationalteamformationorder` — аналогично |
| `teams.formation_xml` | шаблон из схем (4-2-3-1 / 4-3-3…), дефолт GF в `mainmenu.cpp:492` |
| `teams.tactics_xml` | дефолт GF или случайные стили (possession/counter/…) |
| `teams.color1/color2` | `clubs.colors` HEX → «R, G, B» |
| `teams.shortname` | первые 3 буквы (или ручной маппинг топ-клубов) |
| `teams.kit_url` | `images_teams/<лига>/<клуб>` + генератор китов по `template_kit.png` |
| `teams.logo_url` | скачивание с TM + ресайз 128×128 |
| `leagues`, `countries`, `regions` | из `competitions.json` + страны |
| `leagues.tier` | `clubs.json` `tier` лиги → число важности (`tier_to_int` в `mapping.py`): `First Tier`=1 … `Sixth Tier`=6, `Reserve league`=90, `Youth league`=100. Используется для сортировки лиг страны в выборе команды (высший дивизион первым). |
| `leagues.logo_url` | `images_competitions/<TM-ид лиги>.png` — файл именуется **по уникальному TM-id**, а не по имени лиги (иначе одинаково названные лиги разных стран, напр. две «Bundesliga» или несколько «Premier League», писались бы в один файл и показывали чужой логотип). |

### Киты

Кит в GF — PNG 1024×1024 с UV-раскладкой по `template_kit.png`
(`data/databases/default/template_kit.png`), нижняя четверть текстуры не используется.
Генератор — standalone-инструмент `kit-generator` (на машине, `Desktop/projects/kit-generator`):
пакетная генерация + ручной web-редактор.

Регионы шаблона выводятся программно (`kits/regions.py`):
- футболка — y 0–418 (color1-регион `#D3D3D3`);
- шорты — y 419–582, гетры — y 583–766 (второй регион `#FFFFFF` разбит по координатам);
- швы/контуры `#002A00` и фон остаются чёрными.

Затенение — зелёный канал шаблона (трикотаж): `результ = цвет_региона × (G/база)`,
база 211 для футболки, 255 для шортов/гетр.

Палитра клуба: профильные TM-цвета → извлечённые из логотипа (ресайз 48×48, игнор
прозрачности, квантование, топ по частоте+насыщенности) → нейтрали. Узоры футболки:
`plain/stripes/hoops/sash/halves`. Спека хранит индексы в палитре по частям
(shirt/shorts/socks) и комплектам.

**Набор из 6 комплектов на клуб** (`kits/spec.py::auto_specs`):
- `main` — клубные цвета (футболка = первичный, шорты/гетры = вторичный, если он
  белый/чёрный, иначе цвет футболки);
- `white` / `black` — цельные нейтральные (универсальные выездные);
- `reserve` — хроматический цвет из палитры, отличный от main/белого/чёрного;
- `gk1` / `gk2` — два ярких цельных вратарских цвета из стандартного пула
  (зелёный/оранжевый/жёлтый/голубой/маджента).

**Выбор форм на матч** — эталон `kits/spec.py::pick_match_kits` (переносится в C++):
конвенция — home в `main`, гость переодевается при клаше футболок (RGB-дистанция < 60),
при остающемся клаше переодевается и home; ручной оверрайд `manual={"a","b"}`. Вратари
выбираются на матч из `gk1`/`gk2` по мин-контрасту к обеим полевым футболкам.

Два этапа:
1. `generate_kits.py` — палитра + автоподбор + 6 PNG + `specs.json`;
2. `editor/server.py` — клуб за клубом: логотип, цвета, назначение цветов частям формы
   и узор, live-превью, «далее» принимает и автогенерированные сочетания; правки
   сохраняются в `specs.json` (клуб помечается `edited` и не перезаписывается).

**Ловушка**: редактор сохраняет только `specs.json` — PNG он не перерисовывает.
После правок в редакторе обязательно `generate_kits.py --specs <out>/specs.json` +
повторный экспорт в игру, иначе на диске останутся старые киты при новых спеках
(был прецедент: 44 сборных + 4 клуба показывали киты, не совпадавшие со спеками,
напр. Аргентина без белых полос и Бразилия с жёлтыми шортами).

Экспорт в игру — `export_game.py` →
`images_teams/<league_id>/<club_id>_kit_main/white/black/reserve/gk1/gk2.png`
(затем `tm-gf-import` раскладывает по `_kit_01.._06`).
Игра пока грузит только `_kit_01/_02` + общий `goalie_kit.png`; подключение набора китов
и матчевого выбора — правка `team.cpp`/меню (см. `NOTES.md` инструмента).
Текущие 8 команд сохраняют реальные PNG.

## Калибровка 22 статов по FIFA (fifagc)

Исследование-прототип во вьювере данных (каталог `data_max` на машине, `http://localhost:9090`,
120K игроков, 279 лиг): 22 стата GF считаются не «формулой из воздуха» (OVR + позиция + шум),
а из реальных FIFA-атрибутов. OVR калибруется по fifagc, теперь — и распределение статов.

### Источник и скрейпер

- `fetch_fifa_pages.py` — скрейпер страниц игроков fifagc.ru (resume-кэш `fifa_pages.json`,
  ~1.1 rps). Со страницы: 29-34 атрибута (Acceleration, Finishing, Standing Tackle…),
  **Потенциал**, слабая нога, особые приёмы, рост/вес, мульти-позиции. У вратарей +5 своих
  атрибутов (Diving, Handling, Kicking, Reflexes, Positioning).
- 1864 из 120K игроков совпали с fifagc-страницами (матчинг по slug через `fifa_matches.json`);
  11 ошибочных матчингов (страница вратаря-однофамильца на полевого) отсеяны по признаку
  «есть Diving ↔ позиция не GK».

### Маппинг 29-34 атрибутов → 22 стата (`fifa_mapping.py`)

Часть статов — прямые копии, часть — взвешенные смеси. Примеры:
`technical_shot = 0.5·Finishing + 0.25·Long Shots + 0.15·Free Kick + 0.1·Penalties`,
`technical_highpass = 0.7·Long Pass + 0.3·Crossing`, `mental_workrate = 0.5·Stamina + 0.5·Aggression`.
У вратарей reaction/balance/defpos считаются с их атрибутов (Reflexes/Diving/Handling/Positioning).

### Совпавшие vs архетипы (`build_stats_v3.py`)

- **1864 совпавших** — реальные атрибуты со страницы.
- **118K остальных** — архетип позиции: для каждой из 8 групп (GK/CB/FB/DM/CM/AM/W/CF) из
  реальных данных посчитано среднее каждого атрибута и наклон по OVR (OLS cov/var). Стат =
  `среднее_группы + (OVR − средний_OVR_группы) · наклон` + детерминированный разброс ±3 по хэшу
  pid. Профили позиций (что у кого выше/ниже нормы) — `analyze_positions.py`.

### POT / вес / слабая нога / приёмы

- **POT**: у совпавших реальный; у остальных — модель дельты `pot − ovr ~ (ovr, возраст, позиция)`,
  pot никогда не ниже ovr.
- **Вес**: у совпавших реальный; у остальных — регрессия `вес = −41.5 + 0.671·рост(см) + поправка
  позиции` (MAE 3.6 кг).
- **Слабая нога / приёмы**: у совпавших реальные (1-5); у остальных — среднее по позиции
  (слабая нога ≈ 3 везде; приёмы GK=1, CB=2, FB/DM/CM/AM/CF=3, W=4, буст OVR≥85→4, OVR≥90→5).

### Масштаб

Статы во вьювере — **шкала FIFA 0-99**, а GF хранит статы как 0-1 (множители в `match.cpp`,
`GetDefaultProfile`). При переносе в `profile_xml` нужна нормализация (÷100 или через
GF `CalculateStat`).

## Изменения в коде GF

1. `teams.national INTEGER` — колонка; добавить `teams.national` в SELECT в `teamdata.cpp:61`
   (сейчас проверка `national` на строке 74 никогда не срабатывает).
2. Сборные — строки в `teams` (league_id → синтетическая лига «International»), игроки — с
   `nationalteam_id` + `nationalteamformationorder` (запрос в `teamdata.cpp:251` это уже умеет).
3. Реальные имена — осознанное решение (личный проект; в `master` остаются фейковые).
4. **Выбор команд стал трёхступенчатым** (`src/menu/startmatch/teamselect.cpp`): страна →
   лига → команда. Первый пункт списка стран — «National Teams» (id `national`): выбирается
   сборная сразу, без ступени лиги (лига 280 `National Teams`, `country_id = NULL`).
   Дефолт — первая по алфавиту страна; «National Teams» — на индексе 0.
   **Лиги страны сортируются по важности** (`order by coalesce(tier, 99999), name`): высший
   дивизион первым, затем ниже по пирамиде, резервные/молодёжные — в конце. Источник — колонка
   `leagues.tier` (см. маппинг выше; для Англии: PL → Championship → League One → League Two →
   National League → North/South → PL2).
   **Страны без лиг отфильтрованы** (`countries join leagues`): артефакт-страна
   «International» (id 1) оставалась бы тупиком — пустой выбор лиги и SQL-краш
   `near "and"` в `AddTeams` (`where league_id =  and ...`). В `AddLeagues`/`AddTeams`
   добавлен гард на пустой id.
5. **Фото игроков не копируются в сборку**: `faces/` (67 тыс. файлов) в игре не используется,
   `copy_data_post_build` исключает его (`tools/copy_data.cmake`, `PATTERN faces EXCLUDE`).
6. **Защита от битых картинок**: `Gui2Image::LoadImage` проверяет `IMG_Load` на NULL — раньше
   0-байтовый PNG (как `nationalteams.png` после импорта) ронял игру сегфолтом на
   `imageSurfTmp->w`. В `Gui2IconSelector::AddEntry` убран per-entry `Redraw()` (O(n²) при
   больших списках); добавлены `SetSelectedEntry` и `SetSelectable`.
   **Виртуализация иконок**: `AddEntry` больше не создаёт `Gui2Image` на запись — записи стали
   лёгкими (id/caption/путь), а селектор держит пул из 9 иконок и назначает их только записям в
   видимой зоне карусели, загружая картинку при первом появлении. Сотни флагов/логотипов (107
   стран, 246 сборных, 280 лиг) больше не аллоцируют текстуру каждая.
7. **Данные матча**: `formation_xml`/`tactics_xml` у всех команд были NULL — без них матч
   не расставляет состав и зависал после розыгрыша. Залит дефолт 4-2-3-1 и дефолтные тактики
   (из `mainmenu.cpp`); `formationorder` (клубы) и `nationalteamformationorder` (сборные)
   пересобраны: XI = 1 GK + 4 DEF + 5 MID + 1 CF по `base_stat`, бенч = 11+. Команды с <11
   игроками отфильтрованы из выбора (иначе матч виснет).
8. **UI выбора команд**: флаги стран (`images_countries/<id>.png`) — **единый формат 512×512**,
   флаг по центру холста с сохранением собственных пропорций (прозрачные поля), источник —
   flagcdn.com (`w1280`) для ISO-стран + Wikimedia Commons для England/Scotland/Wales/Northern
   Ireland (на flagcdn их нет). Квадратный холст повторяет квадратную иконку карусели (виртуальный
   aspect меню 5:4 → 8%×10% = 1:1). Скрейпер TM отдаёт флаги 12×7 — при регенерации конвейером
   флаги перезаливаются `tools/fetch_flags.py <data_dir> [build_dir]` (маппинг по имени страны).
   Убран «пронос» иконок в углу при смене страны (иконки позиционируются в `Redraw`, а не при
   `AddEntry`), панель игрока 2 строится лениво при открытии. Карусель селектора
   (`src/utils/gui2/widgets/iconselector.cpp`): ввод принимается сразу (без ожидания
   завершения анимации — повторное нажатие немедленно продолжает движение к новому целевому
   элементу), один шаг анимируется ~300 мс (экспоненциальное сглаживание,
   `scrollAnimTime_ms = 300`). Клавиатурный автоповтор — детерминированный в
   `src/utils/gui2/guitask.cpp`: удержание шлёт repeat каждые `keyRepeatInterval_ms = 40`
   после `keyRepeatDelay_ms = 250` (SDL3-события OS-повтора больше не сбивают отсчёт), а
   виджет дополнительно гейтит удержание шагом в `scrollRepeatDelay_ms = 60` — листается
   непрерывно, пока держишь кнопку. **Автоповтор с задержкой удержания**: тап делает 1 шаг
   сразу, повтор начинается только после `scrollHoldDelay_ms = 250` непрерывного удержания и
   идёт каждые `scrollRepeatDelay_ms = 60`; таймер тикает только пока направление удержано
   (`scrollHeld`). Аналоговый стик вблизи дед-зоны дёргается (кадр без события направления
   сбрасывает `scrollHeld`) — без задержки это накапливало шаги и проскакивало объекты; теперь
   стик не проскакивает (у крестовины сигнал чистый цифровой, дёрганий нет).
9. **Тёмные логотипы лиг/команд** (напр. Ligue 1 Алжира — логотип почти целиком чёрный на
   прозрачном фоне) терялись на тёмном фоне селектора. Для селекторов лиги и команды включена
   **белая окантовка по форме логотипа**: `Gui2Image::SetDrawOutline(true)` → при `LoadImage`
   `sdl_addoutline` заливает белым прозрачные пиксели в радиусе `max(w,h)/25` (clamp 2–10) от
   непрозрачной области. **Холст исходника расширяется на радиус по всем сторонам**, так что
   окантовка не обрезается на краях даже у full-bleed логотипов (это же чинит и старый случай —
   логотип не влезал целиком). Окантовка масштабируется вместе с иконкой карусели (считается один
   раз на источник, не per-frame). Флаги стран не окантовываются (`SetDrawOutline` не выставлен).

## Ловушки

- **Игроки без фамилии**: TM хранит часть игроков под одним именем (Endrick, Cézar, Nené…) —
  `last_name` в каноне пустой. В GF SQLite таких ~2.1 тыс. (844 клуба, 26 сборных). Подписи над
  игроками, меню расстановки и сообщения о голах показывали только `GetLastName()`, поэтому над
  таким игроком имя не появлялось вообще (в т.ч. при ручном выборе). Фолбэк — `PlayerData::GetLastName()`
  возвращает имя, если фамилия пустая (`src/data/playerdata.hpp:23`). Конвертеру при желании можно
  выставлять в `last_name` одно имя, но код должен переживать и пустую фамилию.
- **Лимит запросов**: HTML 1.5 rps к TM (безопасное значение по probe 2026-08-29: чисто на 2.0 rps
  sustained, 3.0 rps burst; CDN-картинки не ограничены — 10 rps). Resume-кэш обязателен.
- **`extract_from_url`** в transfermarkt-api должен срезать домен (`https://www...`) и ловить
  `AttributeError` — иначе канонические URL ломают парсинг (починено в форке).
- **Возраст в составе сборной** брать со второго `td.zentriert` (`[2]`), не с первого (номер).
- **Схема парсит int из строк**: `parse_str_to_int` в `schemas/base.py` ожидает строку, int уже
  передавать нельзя.
- **Дубли клубов в источнике**: `data/full/clubs.json` содержит один и тот же клуб (тот же
  `id`) несколько раз внутри одной лиги (2–3×, напр. «Liga AUF Clausura» ×3, российская
  «2. Division A (Phase 1)» ×2). Игра была залита с этими дублями; БД дедуплицирована
  (команда на имя в лиге + игрок на `team_id, firstname, lastname, role`): 4967→4653 команд,
  135898→126826 игроков. Скрейперу стоит не аппендить уже присутствующий клуб в лигу.
