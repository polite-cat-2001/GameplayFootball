# Матч по локальной сети (LAN) — план реализации

Дата: 2026-09-11. Тип: plan. Проектная спека (неизменяемый снимок):
`docs/specs/2026-09-11-lan-match-design.md`. Ветка работы: `lan` (от `squads-update`).

**Goal:** матч по локальной сети (Hamachi/Radmin): хост открывает порт, игроки
подключаются по IP+порту, выбирают стороны в зеркальном лобби, играют до 2 человек
на команду (макс 4 пира с хостом). Хост — авторитет, клиент не симулирует. Хост
не получает преимущества по пингу: все выравниваются по самому медленному.

**Architecture:** host-authoritative, тонкий клиент. Хост симулирует
`Match::Process`, рассылает снапшоты рендер-состояния (поза игрока = `animApplyBuffer`:
анимация + `frameNum` + позиция + ориентация; мяч = позиция + ориентация). Клиент
строит `Match` из потокового `MatchSetup` (хост — источник данных) и проигрывает
снапшоты через штатный Put-пайплайн. Лобби — одно каноническое `LobbyState` на
хосте, зеркалится всем. Топология — звезда.

**Tech Stack:** C++17, Boost (`boost::asio`, `boost::thread`), SDL3 (ввод),
CMake, OpenGL (не трогаем).

## Global Constraints

- **Геймплей не трогаем.** `Match::Process`, AI, мяч, физика — без изменений для
  одиночной игры. Эталон `tools/determinism` для Windows x86
  (`7134def2...`) **не должен сдвинуться** после каждой задачи.
- **Сборка из каталога сборки** с копией `data/`:
  `cmake --build build --config Release`.
- **Boost-идиомы** (`boost::asio`/`thread`/`signal`), не std-замена.
- **Ассеты не меняем.** Клиент использует базовые `media/` из своей сборки; данные
  команд/игроков получает стримом от хоста.
- Ветки `google_brain`/`windows` не трогаем.
- Константы-тюнеры сети — в `src/gamedefines.hpp` + строка в
  `docs/wiki/константы.md` (только там дефолты).
- После каждой задачи: сборка, `determinism check`, обновление вики.

## Зафиксированные решения

- **Данные — ленивый стрим с хоста, не синхронизация БД.** Своя БД клиенту не
  нужна. Каталог команд в лобби — по запросу/страницами (~88 КБ на 4652 имени).
  На старте — только 2 выбранные команды и их `PlayerData` (~60 КБ сырыми,
  ~15–25 КБ с zlib). Киты/лого — локальные файлы `databases/default/images_teams/*`;
  при совпадении базовой `data/` не передаются, кастомные — стримом. Handshake
  проверяет protocol + **хеш медиа-ассетов**, а не версию БД.
- **Fairness — все по самому медленному.** `U = max u_i` (односторонняя задержка),
  `B` — буфер интерполяции. Пир задерживает свой ввод перед отправкой:
  хост `2U`, клиент `i` — `2U - u_i`. Ввод применяется через `2U` после нажатия,
  все рендерят с одинаковым `B`.
- **Лимиты:** 2 человека на команду, максимум 4 пира в лобби, включая хоста.
- **Зритель** — штатная камера.
- **Сессия** живёт, пока хост не закрыл лобби. Keepalive 500 мс по TCP, таймаут
  без пакетов **5 с** = отключён. Реконнект поддержан, но владение стороной не
  возвращается — переподключившийся новый игрок.
- **Пауза равноправна** (любой пир). Хост в паузе меняет формы, погоду, сложность
  AI. Смена клуба в паузе заблокирована; «Выйти в лобби» = завершить матч →
  выбор сторон в текущей конфигурации.
- **Дисконнект/подключение во время матча** → пауза + выбор сторон (аналог
  отключения геймпада, `gametask.cpp:139-180`).
- **Порт:** одно число на TCP и UDP, дефолт `27015`, у клиента предзаполнен.
- **Ввод клиента** — каждый тик (100 Гц), повтор последнего кадра при потере UDP.
- **Снапшоты** — 30–50 Гц + интерполяция, v1 полные (дельты позже).

## Риски

- **Хеш медиа-ассетов** должен совпадать, иначе анимации разъедутся — проверять на handshake.
- **Объём медиа** при кастомных китах: стримить только используемые файлы.
- **Инъекция сетевых устройств** в `controllers`/`SideSelection` — аккуратно с
  hot-plug (`RefreshGamepads`) и `UpdateControllerSetup`.
- **Remote-сцена** не должна случайно звать части симуляции (`ProcessState`,
  реплеи, неттинг) — изолировать флагом.
